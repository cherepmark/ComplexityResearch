# Описание алгоритмов исследования

Формат раздела: описание → идея → псевдокод → теоретическая сложность (Best/Average/Worst)
→ количество элементарных операций → практическое применение → преимущества → недостатки.
Методика измерений — Documentation/BenchmarkMethodology.md; блок-схемы — Documentation/flowcharts.md.

Состав: №1–№9 — стандартные алгоритмы временного бенчмарка; №10–№12 — индивидуальные
(кастомные) алгоритмы. Отдельно — операционный бенчмарк возведения в степень
(приложение в конце документа): n = 1..1000, измеряется количество операций.

---

## №1. Постоянная функция — O(1) (`ConstantAlgorithm`)

**Описание.** Эталон алгоритма постоянной сложности: количество операций не зависит от
размера задачи.

**Идея.** Логическая задача O(1) выполняется за ~1 нс — меньше разрешения `Stopwatch`.
Чтобы время было измеримым, фиксированная операция (целочисленное сложение) технически
повторяется n раз. n здесь — число повторений замера, а не размер задачи: это явно
отделено в коде и в интерфейсе.

**Псевдокод.**
```text
acc ← 0
для i от 1 до n:      # технические повторения
    acc ← acc + 7
```

**Сложность.** O(1) логически; T(n) = C·n относительно числа повторений.

**Количество операций.** На итерацию: 2 сложения (acc и счётчик), 1 сравнение,
1 присваивание.

**Применение.** Доступ по индексу, арифметика, обмен переменных.

**Преимущества.** Мгновенно, не зависит от данных. **Недостатки.** Как учебный замер
требует повторений; чувствителен к конвейеру процессора.

## №2. Сумма элементов массива — O(n) (`SumAlgorithm`)

**Описание.** Один проход по массиву с накоплением суммы в 64-битной переменной.

**Идея.** Каждый элемент обрабатывается константное время → суммарно линейно.

**Псевдокод.**
```text
sum ← 0
для каждого x в массиве:
    sum ← sum + x
```

**Сложность.** O(n), Best = Average = Worst.

**Количество операций.** На элемент: 2 сложения, 1 сравнение, 1 присваивание,
1 доступ к массиву.

**Применение.** Агрегации, средние значения, контрольные суммы.

**Преимущества.** Простота, последовательный доступ. **Недостатки.** JIT может
векторизовать цикл (SIMD) — реальное время лучше «элементарной» модели; для больших n
время ограничено пропускной способностью памяти.

---

## №3. Произведение элементов — O(n) (`ProductAlgorithm`)

**Описание.** Один проход с накоплением произведения **по модулю простого числа**
P = 2³¹ − 1 — защита от переполнения без изменения сложности.

**Псевдокод.**
```text
prod ← 1
для каждого x в массиве:
    prod ← (prod · x) mod P
```

**Сложность.** O(n).

**Количество операций.** На элемент: 2 умножения (умножение + остаток), 1 сложение,
1 сравнение, 2 присваивания, 1 доступ.

**Применение.** Полиномиальные хэши, модульная арифметика.

**Преимущества.** Контролируемое переполнение. **Недостатки.** Остаток от деления дорог.

---

## №4а. Многочлен наивно — O(n²) (`PolynomialNaiveAlgorithm`)

**Описание.** P(x) = a0 + a1·x + … + an·xⁿ; для каждого слагаемого степень x вычисляется
заново внутренним циклом.

**Псевдокод.**
```text
result ← 0
для i от 0 до n:
    xk ← 1
    для j от 1 до i:
        xk ← xk · x
    result ← result + a[i] · xk
```

**Сложность.** O(n²): Σ i ≈ n²/2 умножений.

**Количество операций.** ≈ n²/2 умножений и n²/2 сложений.

**Применение.** Учебный «анти-пример»; черновые вычисления малых степеней.

**Преимущества.** Наглядно показывает цену дублирования работы.
**Недостатки.** Квадратичный рост.

---

## №4б. Метод Горнера — O(n) (`HornerAlgorithm`)

**Описание.** P(x) = (...((an·x + a(n−1))·x + …)·x + a0) — вложенные скобки устраняют
повторное возведение в степень.

**Псевдокод.**
```text
result ← a[n]
для i от n−1 вниз до 0:
    result ← result · x + a[i]
```

**Сложность.** O(n): n умножений и n сложений.

**Количество операций.** На коэффициент: 1 умножение, 1 сложение, 1 сравнение,
1 присваивание, 1 доступ.

**Применение.** Быстрые вычисления многочленов, полиномиальные хэши, системы счисления.

**Преимущества.** Минимум умножений; контраст с №4а. **Недостатки.** Последовательная
зависимость итераций.

---

## №5а. Итеративное возведение в степень — O(n) (`PowerIterativeTimeAlgorithm`)

**Описание.** result ← 1; затем n раз result ← result·a mod m — ровно n умножений.

**Идея.** Лобовое умножение; время линейно по показателю. Так как один вызов занимает
микросекунды, за один замер алгоритм выполняется K = 1000 раз (технические повторения,
как у №1). Показатель n — размер задачи.

**Псевдокод.**
```text
result ← 1
для i от 1 до n:
    result ← result · a mod m
```

**Сложность.** Best = Average = Worst = O(n).

**Количество операций.** ≈ 5n (умножение+остаток, сравнение, присваивания, инкремент), ×K.

**Применение.** Учебный базовый вариант.

**Преимущества.** Простейший код. **Недостатки.** Линейный рост; для сравнения с №5в
даёт в ~50 раз больше операций при n = 1000.

---

## №5б. Рекурсивное возведение в степень — O(n) (`PowerRecursiveTimeAlgorithm`)

**Описание.** power(a,k) = a·power(a,k−1), power(a,0) = 1 — рекурсия глубиной n.

**Псевдокод.**
```text
power(a, k):
    если k = 0: вернуть 1
    вернуть a · power(a, k−1) mod m
```

**Сложность.** O(n) по операциям и по глубине стека (показатель ограничен 5000 —
безопасно для стека 1 МБ).

**Количество операций.** ≈ 6n (умножения, сравнения, вычитания), ×K = 20000.

**Применение.** Демонстрация рекурсии.

**Преимущества.** Наглядность. **Недостатки.** Глубина стека O(n), накладные расходы
вызовов.

---

## №5в. Бинарное возведение в степень — O(log n) (`PowerBinaryTimeAlgorithm`)

**Описание.** Двоичное разложение показателя: основание возводится в квадрат на каждом
шаге, при единичном бите результат домножается.

**Псевдокод.**
```text
result ← 1; b ← a; e ← n
пока e > 0:
    если e нечётно: result ← result·b mod m
    b ← b·b mod m
    e ← e >> 1
```

**Сложность.** Best = Average = Worst = O(log n): ≈ log₂(n) итераций.

**Количество операций.** ≈ 6·log₂(n), ×K = 1 000 000.

**Применение.** RSA, Диффи–Хеллман, биномиальные коэффициенты по модулю.

**Преимущества.** На n = 10⁹ — ~30 итераций вместо 10⁹. **Недостатки.** Рост log n
слабо заметен на линейной шкале (диапазон подобран так, чтобы рост был виден).

---

## №6. Bubble Sort — O(n²) (`BubbleSortAlgorithm`)

**Описание.** Проходы по массиву с обменом соседних элементов; флаг `swapped` даёт
ранний выход (лучший случай O(n) на отсортированных данных).

**Псевдокод.**
```text
для end от n−1 вниз до 1:
    swapped ← false
    для j от 0 до end−1:
        если a[j] > a[j+1]:
            обменять a[j], a[j+1]
            swapped ← true
    если not swapped: прервать
```

**Сложность.** Best O(n) / Average O(n²) / Worst O(n²).

**Количество операций.** Сравнений n(n−1)/2; обменов в среднем n(n−1)/4 (инверсии);
доступов ≈ 2·C + 4·S.

**Применение.** Обучение, почти отсортированные малые данные.

**Преимущества.** Простейший код, стабильность. **Недостатки.** Квадратичное время.

---

## №7. Quick Sort — O(n log n) (`QuickSortAlgorithm`)

**Описание.** Собственная реализация: медиана трёх, разделение по Седжвику, рекурсия
по меньшей части, вставки для отрезков < 16. Не вызов Array.Sort.

**Псевдокод.**
```text
sort(lo, hi):
    если hi−lo+1 < 16: insertionSort(lo, hi); вернуть
    p ← partition(lo, hi)      # медиана трёх
    sort(lo, p−1); sort(p+1, hi)
```

**Сложность.** Best/Average O(n log n), Worst O(n²) (редок на случайных данных).

**Количество операций.** Сравнения ≈ 1.39·n·log₂n; обмены ≈ 0.25·n·log₂n.

**Применение.** Универсальная сортировка (std::sort, Arrays.sort).

**Преимущества.** Быстрая, in-place. **Недостатки.** Неустойчива; возможен худший случай;
память до 10⁸ элементов — 400 МБ.

---

## №8. TimSort — O(n log n) (`TimSortAlgorithm`)

**Описание.** Собственная упрощённая реализация: естественные серии (с разворотом
убывающих), вставки до minrun (32..63), стек серий с инвариантами баланса, стабильные
слияния через буфер меньшей стороны.

**Псевдокод.**
```text
minrun ← calcMinRun(n)
пока есть элементы:
    run ← естественная серия с i (убывающая → разворот)
    если короче minrun: дотянуть вставками
    push run; mergeCollapse()
слить оставшиеся серии
```

**Сложность.** Best O(n) (отсортированные данные), Average/Worst O(n log n).

**Количество операций.** ≈ n·log₂n сравнений, 2·n·log₂n перемещений.

**Применение.** Стандарт Python (list.sort) и Java (Object[]).

**Преимущества.** Стабильность, адаптивность. **Недостатки.** Сложнее; O(n/2) буфера.

---

## №9. Классическое умножение матриц — O(n³) (`MatrixMultiplicationAlgorithm`)

**Описание.** C = A·B тройным вложенным циклом: C[i,j] = Σ A[i,k]·B[k,j].

**Идея.** Для каждой пары (i, j) суммируются n произведений — n³ умножений и n³
сложений. Порядок циклов i-k-j — последовательное чтение строки B (кэш).

**Псевдокод.**
```text
для i, k, j:
    c[i,j] ← c[i,j] + a[i,k] · b[k,j]
```

**Сложность.** Best = Average = Worst = O(n³).

**Количество операций.** n³ умножений + n³ сложений + ~3n³ накладных + ~4n³ доступов.

**Применение.** Графика, СЛАУ, графы, базовые операции нейросетей.

**Преимущества.** Простой эталон кубической сложности. **Недостатки.** Проигрывает
Штрассену и BLAS на больших n; память 3·n² элементов.

---

## №10. Индивидуальный: быстрое возведение в степень — O(log n) (`CustomAlgorithm`)

**Описание.** aⁿ mod m двоичным возведением (то же ядро, что №5в, но замер
без адаптера-дубликата: K = 200 000 повторений на замер). Образец кастомного
алгоритма студента.

**Псевдокод.**
```text
result ← 1; b ← a mod m; e ← n
пока e > 0:
    если e нечётно: result ← result·b mod m
    b ← b·b mod m
    e ← e >> 1
```

**Сложность.** Best = Average = Worst = O(log n).

**Количество операций.** ≈ 3·log₂(n) умножений на итерацию (квадрат+остаток,
домножение при бите), ×K.

**Применение.** RSA, Диффи–Хеллман, модульная арифметика.

**Преимущества.** Логарифмический рост, нет больших массивов. **Недостатки.** Рост
слабо заметен на линейной шкале.

---

## №11. Индивидуальный: алгоритм Кадане — O(n) (`KadaneAlgorithm`)

**Описание.** Максимальная сумма непрерывного подмассива за один проход.

**Идея.** maxEnding — лучшая сумма, заканчивающаяся в позиции i (продолжить предыдущий
подмассив или начать новый); maxSoFar — глобальный рекорд. Один проход, O(1) памяти.

**Псевдокод.**
```text
maxEnding ← 0; maxSoFar ← −∞
для каждого x в массиве:
    maxEnding ← max(x, maxEnding + x)
    maxSoFar  ← max(maxSoFar, maxEnding)
```

**Сложность.** Best = Average = Worst = O(n).

**Количество операций.** На элемент: 3 сложения, 3 сравнения, 2 присваивания,
1 доступ к массиву.

**Применение.** Максимальная прибыль по дням, анализ временных рядов, биоинформатика.

**Преимущества.** Один проход, константная память, ветвящийся (нетривиальный) поток.
**Недостатки.** Ветвления дороже линейных «потоковых» операций из-за промахов
предсказателя. Данные содержат отрицательные значения — иначе задача вырождается.

---

## №12. Индивидуальный: реверс массива — O(n) (`ReverseArrayAlgorithm`)

**Описание.** Оборот массива на месте двумя указателями: обмен a[i] ↔ a[n−1−i],
указатели идут от краёв к центру.

**Псевдокод.**
```text
i ← 0; j ← n−1
пока i < j:
    обменять a[i], a[j]
    i ← i + 1; j ← j − 1
```

**Сложность.** Best = Average = Worst = O(n): n/2 обменов, O(1) памяти.

**Количество операций.** На элемент: 0.5 обмена, 1 сложение, 0.5 сравнения,
2 доступа к массиву.

**Применение.** Обработка строк и буферов, разворот истории, подготовка данных для стека.

**Преимущества.** Минимум дополнительной памяти, симметричный доступ к памяти.
**Недостатки.** Запись по двум фронтам массива; повторные проходы чередуют порядок
(объём работы на проход одинаков).

# Приложение. Операционный бенчмарк возведения в степень (n = 1..1000)

Отдельный режим (кнопка «Возведение в степень»): измеряется НЕ время, а количество
элементарных операций — счётчик инкрементируется внутри алгоритма. График: X = n,
Y = операций; три кривые на одном графике.

### Итеративный — O(n) (`PowerIterativeAlgorithm`)

result ← 1; n раз result ← result·a mod m. Измеренно: ≈ 5n операций
(умножение+остаток, присваивание, сравнение, инкремент).

### Рекурсивный — O(n) (`PowerRecursiveAlgorithm`)

power(a,k) = a·power(a,k−1). Измеренно: ≈ 6n операций (плюс вызовы).

### Бинарный — O(log n) (`PowerBinaryAlgorithm`)

Двоичное разложение показателя. Измеренно: ≈ 5·log₂(n) + 3·popcount(n) операций.
Для n = 1000: итеративный ≈ 5000 операций, бинарный ≈ 80 — разница ~60x.

### Двумерный эксперимент A(n×m)·B(m×n) — тепловая карта

Отдельный вид эксперимента (кнопка «Матрицы A(n×m)·B(m×n)»): для НАБОРА значений
n и НАБОРА значений m (два независимых диапазона со своими Start/Nmax/step)
перемножаются прямоугольные матрицы A(n×m)·B(m×n) = C(n×n) и собираются ВСЕ
тройки (n, m, время) — без разбиения по m на отдельные кривые.

**Визуализация** — два связных представления одних и тех же троек
(переключатель на панели графика, по умолчанию 3D):
- **3D-поверхность** (`Surface3DControl`, WPF Viewport3D): ось X = n,
  ось Z (глубина) = m, высота по Y = время; цвет грани дублирует высоту
  той же шкалой; ЛКМ — вращение, колесо — зум, двойной клик — сброс;
  все тройки (n, m, время) показываются одной объёмной поверхностью.
- **Тепловая карта** (`HeatmapControl`): ось X = n, ось Y = m, цвет ячейки = время
  (синий → зелёный → жёлтый → красный), справа colorbar с min/max. В ячейках
  подписано время (если сетка ≤ 8×8), под курсором — точные значения.

**Теория**: t(n, m) ∝ n²·m (n² ячеек результата, по m умножений каждая);
программа подбирает t = C·n²·m по МНК и показывает MSE.

**Защита от долгого выполнения**: перед запуском программа считает
общее число замеров = (кол-во n) × (кол-во m) × (запусков + прогрев) и
предупреждает, если оно > 500 или максимум оси ≥ 500 при маленьком шаге.
В БД эксперимент хранится отдельно (тег режима «MATNM», колонка M).
