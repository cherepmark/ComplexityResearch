# ComplexityResearch

Учебное WPF-приложение (C#, .NET 9) для **эмпирического анализа временной
сложности алгоритмов и разработки системы тестирования**: измеряет фактическое
время выполнения, сравнивает с теоретической моделью T(n) = Σ countᵢ·costᵢ,
строит аппроксимацию Tapprox(n) = C·f(n) с оценкой качества MSE, хранит
результаты в SQLite с кэшем и включает операционный бенчмарк возведения
в степень (подсчёт элементарных операций).

## Возможности

- **14 алгоритмов + 3 варианта возведения в степень (операционный бенчмарк):**
  №1 константа O(1); №2 сумма O(n); №3 произведение O(n) (модульная арифметика);
  №4а многочлен наивно O(n²); №4б метод Горнера O(n);
  №5а/5б/5в возведение в степень итеративно O(n) / рекурсивно O(n) / бинарно O(log n);
  №6 Bubble Sort O(n²); №7 Quick Sort O(n log n) average / O(n²) worst
  (собственная реализация, медиана трёх); №8 TimSort O(n log n) (собственная
  реализация); №9 умножение матриц O(n³);
  индивидуальные (кастомные): №10 быстрое возведение в степень O(log n),
  №11 алгоритм Кадане O(n), №12 реверс массива O(n).
  Отдельный операционный бенчмарок степеней: итеративный O(n), рекурсивный O(n),
  бинарный O(log n) — измеряется количество операций (n = 1..1000).
- **Benchmark:** Nmax + step (линейная сетка n), 5 запусков по умолчанию
  (+ прогревочные), Seed, лимит времени точки, только чистое выполнение
  алгоритма (данные/память/БД/GUI — вне таймера), `Stopwatch`, Release.
- **БД и кэш:** SQLite; на каждый запуск отдельная строка
  (Algorithm, n, RunNumber, ElapsedTime, StepCount, ExperimentDate) плюс
  параметры эксперимента и теоретическое значение. Ключ кэша =
  алгоритм + n + параметры; «Use cache» берёт готовые результаты,
  «Force recalculation» удаляет ключ перед пересчётом (без смешивания).
- **Аппроксимация и MSE:** Tapprox(n) = C·f(n) (МНК через начало координат);
  MSE = (1/k)Σ(T_эмп − Tapprox)² — в GUI рядом с графиком, в таблице,
  в экспорте и в БД.
- **Графики:** эксперимент + теоретическая модель + аппроксимация, MSE
  в заголовке; обычная/логарифмическая шкала, зум/пан, экспорт PNG;
  для возведения в степень — график «операции vs n».
- **GUI:** выбор алгоритма, Nmax, step, запусков, Seed, кэш, запуск/остановка,
  принудительный пересчёт, таблица, график, прогресс, авторский вывод;
  UI не блокируется (эксперимент в фоновом потоке).
- **Тесты:** xunit — алгоритмы, сортировки, многочлены, матрицы, степени,
  счётчик операций, аппроксимация, MSE, БД/кэш, конфигурации, интеграция.

## Сборка, запуск, тесты

Требуется .NET SDK 9 и Windows.

```bash
dotnet build -c Release                                  # сборка
dotnet run -c Release --project ComplexityResearch.csproj # запуск GUI
dotnet test ComplexityResearch.Tests -c Release           # unit-тесты
```

Или откройте `ComplexityResearch.sln` в Visual Studio 2022, конфигурация **Release**, F5.

> **Важно:** измерения корректны только в Release. В Debug JIT не оптимизирует
> код, и результаты искажаются в несколько раз.

## Как измеряется время

1. Точки n = StartN, StartN+step, …, Nmax (включён всегда).
2. Данные генерируются с фиксированным seed **вне таймера**; сортировки
   получают свежую копию на каждый запуск.
3. Первый запуск точки — прогревочный (JIT, кэш), не учитывается.
4. Замер — `Stopwatch`; 5+ запусков на точку; среднее/min/max/σ;
   отдельные запуски сохраняются в БД.
5. Теория: T(n) = Σ countᵢ·costᵢ; калибровка констант — кнопкой в GUI.
6. Аппроксимация C·f(n) по МНК; MSE качества приближения.

## БД и кэш

SQLite (`%LOCALAPPDATA%\ComplexityResearch\benchmark.db`): таблицы
`Experiments` (параметры, константы, MSE, вывод) и `Measurements`
(отдельные запуски). Ключ кэша — SHA-256 от алгоритма + n + параметров
эксперимента + констант стоимости. «Use cache» — переиспользование,
«Force recalculation» — удаление ключа и полный пересчёт без смешивания
старых и новых данных. Подробности — `Documentation/Database.md`.

## Прямой и масштабированный режимы

Для линейных алгоритмов при n > 50 000 000 массив размером n не выделяется:
обрабатывается блок 50 млн элементов с числом проходов, пропорциональным n
(пометка «Масштабированный» в таблице и отчёте). Сортировки всегда прямые.

## Добавление нового алгоритма

1. Класс-наследник `AlgorithmBase` (или `IOperationCountedAlgorithm`).
2. Реализация обязательных членов (имя, сложность, конфигурация, данные,
   ядро, счётчик операций).
3. Одна строка в `AlgorithmRegistry`.
Сервисы, график, таблица, БД и экспорт менять не нужно.
