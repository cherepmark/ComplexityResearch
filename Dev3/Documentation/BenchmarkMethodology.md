# Методика бенчмаркинга

## Что измеряется

Только выполнение ядра алгоритма (`ExecuteCore`). НЕ измеряются:
генерация данных, выделение массивов/матриц и буферов, БД, графики, GUI,
экспорт, вывод на экран. Подготовка данных выполняется до запуска таймера
(`PrepareInput` / `PrepareRunInput` — вне `Stopwatch`).

## Таймер и окружение

- `System.Diagnostics.Stopwatch` (счётчик высокого разрешения), не `DateTime.Now`;
- конфигурация **Release** (в Debug JIT не оптимизирует — время искажается);
- JIT-прогрев: весь алгоритм прогоняется на малом n до серии; первый запуск
  каждой точки — прогревочный (кэш процессора после генерации данных);
- защита от оптимизации: результат алгоритма «утекает» в статическое поле
  (`PreventOptimization`), JIT не может удалить вычисления;
- в измеряемом коде нет аллокаций → GC не влияет; между точками — явная
  сборка мусора до выделения нового большого массива;
- входные данные одинаковые для всех запусков точки (seed фиксирован);
  сортировки получают свежую копию данных на каждый запуск (вне таймера).

## Параметры эксперимента

| Параметр           | Значение по умолчанию | Комментарий                                     |
|--------------------|----------------------|-------------------------------------------------|
| StartN             | свой для алгоритма   | первая точка                                     |
| Nmax               | свой для алгоритма   | последняя точка, включается всегда               |
| step               | свой для алгоритма   | линейная сетка n                                 |
| запусков на точку  | 5                    | настраивается; сверх них 1 прогревочный запуск   |
| Seed               | 20260914             | воспроизводимость данных                         |
| лимит времени точки| 15 с                 | превышение → корректная остановка эксперимента   |

## Эмпирический подбор Nmax

Nmax для каждого алгоритма подобран экспериментально: время на максимальной
точке ≈ 5–10 с, чтобы эксперимент не «зависал»:

| Алгоритм            | Nmax      | Время макс. точки (ориентир) |
|---------------------|-----------|------------------------------|
| Константа O(1)      | 3·10⁹     | ~1–2 с                        |
| Сумма O(n)          | 3·10⁹     | ~2 с (память ~12 ГБ/с)        |
| Произведение O(n)   | 10⁹       | ~5 с (остаток от деления дорог)|
| Многочлен наивно    | 50 000    | ~1.5 с (n²/2 умножений)       |
| Горнер              | 1.5·10⁹   | ~6 с                          |
| Bubble Sort         | 50 000    | ~2–3 с                        |
| Quick Sort          | 10⁸       | ~10 с (400 МБ массив)         |
| TimSort             | 7·10⁷     | ~9 с (280 МБ массив)          |
| Умножение матриц    | 600       | ~2–5 с (2·600³ операций)      |
| Индивидуальный      | 100 000   | ~10 мс (K повторений на замер)|

Дополнительно `MaxSecondsPerPoint` страхует от «зависания» при ручном
увеличении Nmax.

## Прямой и масштабированный режимы

- **Прямой** (n ≤ 50 000 000): массив размера n реально выделяется.
- **Масштабированный** (линейные алгоритмы, n > 50 млн): обрабатывается блок
  50 млн элементов, число проходов пропорционально логическому n. Суммарный
  объём работы пропорционален n, но массив размером n не выделяется. Такие
  точки помечаются «Масштабированный» и не выдаются за полное физическое
  измерение. Сортировки всегда прямые (n log n не декомпозируется линейно).

## Статистика

По K = 5+ учитываемым запускам каждой точки: среднее, min, max, стандартное
отклонение; отдельные запуски хранятся в БД (по строке на запуск).

## Возведение в степень — особый режим

Для итеративного/рекурсивного/бинарного возведения (n = 1..1000) измеряется
НЕ время, а количество элементарных операций: счётчик инкрементируется в
каждой точке алгоритма, где выполняется операция (умножение, сравнение,
присваивание, сдвиг). График: X = n, Y = операций. Ожидания: O(n), O(n),
O(log n).

## Влияние аппаратуры (для анализа расхождений)

- иерархия кэша: доступ из ОЗУ в 10–50 раз дороже L1 (потоковые алгоритмы
  упираются в пропускную способность памяти);
- SIMD-векторизация JIT занижает время простых циклов относительно
  «элементарной» модели;
- порядок циклов меняет константу без изменения сложности
  (пример — i-k-j в умножении матриц);
- планировщик ОС и фоновые процессы — источник выбросов (их видно по max
  и стандартному отклонению).

Низкий MSE подтверждает соответствие данных форме f(n), но не является
абсолютным доказательством правильности теоретической модели.
